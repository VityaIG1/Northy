# Интеграция реального прокси-ядра (Xray-core) в Northy + проводка через Codemagic

## Context

Приложение сейчас не работает как VPN: `NorthyTunnel/ProxyCoreController.swift` ищет ядро через `dlsym`, но ни LibXray, ни sing-box в проект не линкуются — `invokeDynamicCoreStart` не находит символ, `startCore` всё равно возвращает `.success` (readiness-таймаут нефатален, `ProxyCoreController.swift:83-91`), и `TUNPacketBridge` молча уходит в fallback (прямой/VLESS-lite). Конфиг-билдер (`HappLinkParser.buildXrayCoreConfiguration`, `Shared/Parser/HappLinkParser.swift:758-1074`) уже генерирует валидный Xray JSON (socks 10808, http 10809, DNS dokodemo 10853), а роутинг использует `geoip:private` / `geosite:category-ru` — значит, нужны ещё geo-ассеты.

**Выбор ядра — Xray-core через официальную обёртку [XTLS/libXray](https://github.com/XTLS/libxray)** (не sing-box): конфиг-билдер пишет именно Xray-формат JSON, а у libXray есть стабильный C-мост `CGoInvoke`/`CGoFree`, который встаёт ровно на существующую dlsym-архитектуру. Сборка идёт в Codemagic (mac_mini_m1), ядро собираем из исходников в CI, в репозиторий бинарники не коммитим.

**Контракт libXray (проверен по исходникам `invoke_model.go`, `cgo_bridge/main.go`, тег v26.x):**
- `char* CGoInvoke(char* requestJSON)` / `void CGoFree(char*)`
- Запуск: `{"apiVersion":3,"method":"runXray","payload":{"xrayJson":"<конфиг>"}}` → ответ `{"success":bool,"data":{},"error":"..."}`
- Остановка: `{"apiVersion":3,"method":"stopXray"}`. Каждый ответ освобождать через `CGoFree`.
- Сборка: `gomobile bind -target ios -iosversion 15.0 -o LibXray.xcframework ./cgo_bridge` → статический фреймворк; символы доступ­ны через `dlsym(nil)`.

## Изменения

### 1. Новый `scripts/build_libxray.sh` (CI-сборка ядра + geo-ассеты)
- Параметры через env: `LIBXRAY_TAG` (по умолч. `v26.10.31`), `SKIP_IF_BUILT=1`.
- Skip-логика: если `Frameworks/LibXray.xcframework` существует и маркер-файл `Frameworks/LibXray.tag` совпадает с `LIBXRAY_TAG` — выход (для кэша Codemagic).
- Иначе: проверяет `go` на PATH, `go install golang.org/x/mobile/cmd/gomobile@latest && gomobile init`; shallow-клон XTLS/libXray в `Vendor/libxray` на тег; `gomobile bind -target ios -iosversion 15.0 -ldflags "-s -w" -o Frameworks/LibXray.xcframework ./cgo_bridge`; пишет маркер тега.
- Скачивает geo-ассеты в `Frameworks/geo/`: `geoip.dat` + `geosite.dat` (Loyalsoldier/v2ray-rules-dat, `latest/download`, с проверкой размера файла >0).
- Gate: `nm -gU` на arm64-срезе бинарника должен показывать `CGoInvoke` и `CGoFree` — иначе exit 1 с понятным сообщением.

### 2. `project.yml` — линковка ядра и ресурсы
- Таргет `NorthyTunnel`:
  - `dependencies:` добавить `- framework: Frameworks/LibXray.xcframework` c `embed: false` (фреймворк статический — символы попадут в сам бинарник appex, embed не нужен).
  - `settings.base.OTHER_LDFLAGS: "$(inherited) -ObjC"` — **критично**: ни один Swift-символ не ссылается на фреймворк (всё через dlsym), без `-ObjC` линкер вырежет весь Go-код как мёртвый.
  - В `sources` добавить `Frameworks/geo` с `buildPhase: resources` (geoip/geosite внутри appex).
- `.gitignore`: добавить `Frameworks/` (xcframework и geo собираются в CI, в git не попадают).

### 3. `NorthyTunnel/ProxyCoreController.swift` — адаптер на реальный API
- Убрать `#if canImport(LibXray)` / `#if canImport(Libbox)` импорты и компилтайм-блок вызова (сигнатура там всё равно не совпадала бы); оставить только dlsym-путь, но переписать его на актуальный контракт:
  - `invokeDynamicCoreStart` → `CGoInvoke`: собирает request-JSON (`apiVersion:3, method:"runXray", payload:{xrayJson}`), читает `String(cString:)`, освобождает через `CGoFree`, парсит `{"success","error"}`. Легаси-фолбэк `LibXrayRunXrayFromJSON` оставить.
  - `invokeDynamicCoreStop` → `stopXray` через `CGoInvoke` (+ легаси `LibXrayStopXray`).
  - **Честные ошибки**: если ни `CGoInvoke`, ни `LibXrayRunXrayFromJSON` не найдены → `.failure("CORE_LIBRARY_NOT_LINKED")` вместо тихого «успеха» (`startCore:83-91`); `error` из ответа ядра пробрасывается в `.failure` (fail-fast уже подключён в `PacketTunnelProvider.swift:75-81`).
  - `waitForCoreReady` таймаут 800 → 3000 мс (нефатальный, мост перепроверяет порт на каждое соединение).
- Добавить `installGeoAssetsIfNeeded()`: копирует `geoip.dat`/`geosite.dat` из `Bundle(for: ProxyCoreController.self)` в `SharedTunnelStore.assetsDirectoryURL` (env `XRAY_LOCATION_ASSET` уже указывает туда, `ProxyCoreController.swift:39-42`), вызывается в начале `startCore`.

### 4. `scripts/build_ipa.sh` — xcodegen + sanity-гейты
- Новый шаг [0/5]: установить `xcodegen` через brew при отсутствии и выполнить `xcodegen generate` (проект теперь генерируется из `project.yml`; коммитить pbxproj больше не требуется — CI регенерит его каждый билд).
- Версия IPA берётся из `project.yml` (grep `MARKETING_VERSION`) вместо хардкода `v0.4.0` в трёх местах.
- После копирования Payload: `nm`-гейт на `PlugIns/NorthyTunnel.appex/NorthyTunnel` — бинарник обязан содержать `CGoInvoke` (fail билда, не warning).

### 5. CI: `codemagic.yaml` и `.github/workflows/build-ipa.yml`
- codemagic: `max_build_duration: 30 → 60`; скрипты: 1) `brew install go xcodegen` + `scripts/build_libxray.sh`, 2) `./scripts/build_ipa.sh`; кэш `~/go/pkg/mod` и `Frameworks/` (пересборка ядра только при смене тега; повторные билды ускоряются на ~10–15 мин).
- GH workflow: шаг `actions/setup-go@v5` + запуск `scripts/build_libxray.sh` перед `build_ipa.sh` (кэш Go-модулей включён).

### 6. `README.md`
- Обновить раздел локальной сборки: перед `build_ipa.sh` нужен macOS с Go (`brew install go`) и запуск `./scripts/build_libxray.sh`; описать переменные `LIBXRAY_TAG`.

## Verification
- Локально (Linux): `bash -n` на все скрипты; YAML-валидация `codemagic.yaml`/workflow через python-yaml; сверка request-JSON адаптера с `invoke_model.go` (apiVersion 3, метод `runXray`, поле `payload.xrayJson`).
- Реальная проверка — запустить Codemagic-билд (у меня нет macOS/Xcode): гейты `nm` и `xcodegen` поймают проблемы линковки на этапе CI. В готовом IPA должен пройти `codesign --verify`, а на устройстве: включить туннель → в логах `Proxy core SOCKS5 listener active on 127.0.0.1:10808`, телеметрия скорости ненулевая, сайты открываются через узел.
- Известное ограничение: `codemagic.yaml` не выполнялся в этом окружении — первый запуск CI покажет фактическое поведение (логиCodemagic пришлём для разбора, если что-то упадёт).
